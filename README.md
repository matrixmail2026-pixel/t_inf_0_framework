# T_inf_0 Analytical Identity Framework

T_inf_0 is an analytical identity framework designed to combine live syndication, boundary analysis, and missing-person case monitoring into a single automated feed pipeline. It uses a structured XML/RDF output, tracks repository state via git log metadata, and can be scheduled with cron for periodic refreshes.

## Features

- Live web fetch against The Charley Project public portal
- Cached fallback data when the live endpoint is unavailable
- Boundary-collapse analysis logic for 0 == ∞ scenarios
- Chiral system verification workflow for off-grid identity traces
- RSS 1.0 / RDF syndication feed generation
- Git log integration for recent repository activity metadata
- Cron-ready execution script for automated refreshes

## Running locally

```bash
python3 t_inf_0_framework.py
```

This writes the latest syndication data to `feed.xml` in the repository root.

To generate a custom output path:

```bash
python3 t_inf_0_framework.py --feed /tmp/t_inf_0_feed.xml
```

## Cron scheduling

Use cron to refresh the feed automatically.

```bash
crontab -e
```

Add a schedule, for example:

```cron
0 * * * * /bin/bash /absolute/path/to/t_inf_0_framework/run_cron_update.sh
```

or daily:

```cron
0 0 * * * /bin/bash /absolute/path/to/t_inf_0_framework/run_cron_update.sh
```

The cron script executes the framework and appends output to `cron_execution.log`.

## Output format

The project generates RDF/XML syndication data compatible with feed readers and lightweight XML processing pipelines.

Example structure:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<rdf:RDF xmlns:rdf="http://www.w3.org/1999/02/22-rdf-syntax-ns#" xmlns="http://purl.org" xmlns:sy="http://purl.org">
  <channel rdf:about="https://charleyproject.org">
    <title>T_inf_0 Identity Framework - Charley Project Activity Monitor</title>
    <link>https://charleyproject.org</link>
    <description>Automated analytical tracking for cold-case updates.</description>
    <sy:updatePeriod>hourly</sy:updatePeriod>
    <sy:updateFrequency>1</sy:updateFrequency>
    <sy:updateBase>2026-10-02T00:00:00Z</sy:updateBase>
  </channel>
</rdf:RDF>
```

## Notes

- The live scraper is intentionally resilient and will fall back to a known cached case if the portal is unavailable.
- The project is intentionally lightweight and does not require external dependencies.
- The automation is designed for research and syndication workflows rather than production-grade public API consumption.
